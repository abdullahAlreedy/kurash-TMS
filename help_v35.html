2. Recommended Tournament Flow

  1. Open index.html and enter the portal password.
  2. Open Main Web.
  3. Create a Local Tournament for offline-first operation, or connect the server and create/load the tournament.
  4. Open Settings and confirm tournament type, Gillams, weights/groups, durations, and referee assignment rules.
  5. Add/import players in Players.
  6. Add/edit referee master data only in Referees.
  7. Generate the draw.
  8. Use Referee Management for assignments, final pool, conflicts, and evaluations.
  9. Operate Scoreboard v35 from the same server/tournament.

3. Home vs Settings

  • Home: server connection, tournament creation/loading, backup/restore, readiness check.
  • Settings: tournament rules/config only: Gillams, weights, age groups, duration, referee assignment mode.
  • Server connection should remain in Home, not Settings.

4. Hybrid Offline / Server Mode

  • Offline-first: the system can run without server.
  • Server optional: enter server URL in Home, then Test/Load/Sync.
  • Unsynced changes: export JSON backup and sync later.
  • Recommended server URL: https://kurash-tms.onrender.com

5. Gillam Terminology

Kurash uses Gillam, not Mat. v35 uses Gillam in the interface and help documentation.

  • All Gillams: chairperson can manage all matches.
  • Specific Gillam: Gillam supervisor can manage only that Gillam’s matches.
  • Gillam refs only: shows referees assigned to that Gillam pool.
  • Include global referees: allows global referees when needed.

6. Referees vs Referee Management

  • Referees tab: add, edit, delete referee master data.
  • Main Web Referee Management: normal in-app assignment, final pool, evaluation, performance profile, and conflict review.
  • External Referee Management: open referee_management_screen_v35.html for the Referee Committee Chair in large tournaments.
  • The external screen must connect to the backend server and load the current tournament.

7. Referee Evaluation

v35 supports evaluation for all three officials in each bout:

  • Main Referee
  • Judge 1
  • Judge 2

Evaluations contribute to the referee performance profile and help select officials for finals.

8. Global Referee Conflict Rule

Global conflict gap = 1

  • A global referee is blocked from working in different Gillams at the same bout order.
  • The same global referee is also blocked from different Gillams within ±1 bout order.
  • This is designed to prevent impossible movement between Gillams and reduce operational conflicts.

9. Scoreboard Controls

  • Space: start/stop timer unless typing in an input field.
  • Single click on timer: start/stop timer.
  • Double click on timer: edit match time manually.
  • Gillam / age group / weight are enlarged for visibility.
  • Use withdrawal buttons for no-show or withdrawal scenarios.
  • Double withdrawal = No Contest, no winner, no points, and bracket slot becomes empty.

10. Backup and Recovery

  • Use Export JSON Backup before, during, and after the tournament.
  • Use Restore JSON Backup if browser/server data is lost.
  • Use CSV export for league standings when needed.
  • Keep the old files as backup until v35 is fully tested on a complete tournament.

11. Troubleshooting

  • Black screen: confirm you are using v35 files and open the browser console to read the exact error.
  • Scoreboard not updating: reload from the same server URL and current tournament.
  • External Referee Management shows zero bouts: connect/load from the server first.
  • Result not visible in Main Web: use Refresh/Load Current Tournament or wait for live refresh if connected.
  • GitHub file rename: update links in index.html after renaming files.
